# Content licenses

## Rights scope

This file registers **audio and fonts**. Editorial rights — prose, translations, notation, the
MaqamWorld name, advisor contributions — are decided in `docs/phase0/rights-triage.md`.

Pack 1 copies no MaqamWorld prose, translation, notation, or audio. Its only ship audio is
commissioned material with a signed assignment, so the MaqamWorld rights gate does not block
shipping. Commission and advisor evidence is tracked in the triage document, §5.

## Target pack: 15 masters per maqam

The locked Pack 1 contract is **15 masters per maqam** (3 maqams = 45) plus 5 onboarding drills,
**50 assets total**; the first win reuses the Hijaz signature. Slow playback is runtime `0.75×`,
not separate files. See `docs/phase0/pack1-tuning-worksheet.md` for the signed tuning and
`docs/phase0/content-acquisition-plan.md` §6.1 for the slot breakdown. Until a licensed pack is
recorded, the synthesized clips above are the only content allowed in shipping builds. The current
`drone-c4.mp3` is one shared placeholder; the target pack has one commissioned drone loop per maqam
(worksheet §5 and §7).

### Sourcing options (pick one per batch, record which)

1. **Commissioned recordings** — pay a performer/arranger for original instrumental phrases in the
   maqam, with a written assignment of rights covering mobile app distribution.
2. **Game-compatible royalty-free library** — purchase a license that explicitly permits use in
   mobile games/apps (not video-only), worldwide, perpetual, with no per-download reporting.
3. **CC0 / public-domain recordings** — verify that both the composition and the recording are
   free of restrictions and that no Content ID system claims them.

Commercial recordings and YouTube rips are never allowed, even as placeholders.

### Per-batch pipeline

1. Pre-screen the license for mobile-app use, territory, term, and Content ID claims.
2. Store the license text/contract in the evidence archive and add a row to the register below.
3. Process one 2–4 s phrase per item (scales 4–6 s, drone 30–60 s), mono, MP3 64–128 kbps, lowercase
   filename with no spaces, named `NN-slug.mp3` in `app/src/main/assets/content/audio/`.
4. Add the maqam or phrase to `maqams.json` with a unique `id`, `status: "approved"`, and a valid
   `#RRGGBB` color.
5. Run `./gradlew :app:testDebugUnitTest` — `BundledMaqamPackTest` must pass with all audio present.
6. Play every new phrase on a phone speaker before merging.

### Editorial rules

- Every phrase must be an original note sequence; do not transcribe a famous recording.
- A phrase must be recognisable as its maqam without seeing the title or card.
- Keep phrases short enough to replay comfortably: 2–4 s, scales 4–6 s.
- Do not ship two phrases that are identical or trivially the same melody.
- Replace the synthesized placeholder set completely before the store build.

## Replacing the placeholders with a licensed pack

Do not upload a replacement clip until all of the following are recorded here:

1. **Content name and maqam id** it belongs to.
2. **Rights holder** and **license type** (original work, CC0, purchased royalty-free, commission
   with written assignment, etc.).
3. **License text or contract reference** (file path or URL).
4. **Territory and term** (worldwide/perpetual preferred).
5. **Proof that app/sync use is allowed** — many "royalty-free music" licenses cover videos but
   not mobile apps. Check explicitly.
6. **Source file** and the processed version (trim, fade, loudness normalization).

### Legal guardrails

- **Recordings and compositions** are protected; a re-recorded phrase still needs a
  mechanical/sync license for the composition.
- Do not use commercial clips, YouTube rips, or "no copyright" compilations of commercial music.
- Do not transcribe a famous melody for a placeholder. The current synthesized phrases are original
  note sequences.
- Keep license evidence for every clip, even after launch.

### Audio processing checklist

- 2–4 s phrase starting on the first note (scales 4–6 s; drone 30–60 s loopable).
- Trim silence; 150–300 ms fade-in and fade-out.
- 44.1 kHz, mono, MP3 64–128 kbps or AAC, lowercase filename with no spaces.
- Loudness approximately −16 LUFS integrated, true peak ≤ −1 dBTP.
- Verify the phrase is clear on a phone speaker, not only headphones.
- Keep the original lossless source outside the APK, backed up with the license.

## Site data (`site/public/data/`)

On 2026-11-10 the owner added a MaqamWorld crawl to the public site: 139 pages, 614 track rows,
997 media files, and a SQLite database. The owner states that public use is approved; the approval
reference has not yet been filed here.

This data is the canonical catalog for the site and the source of the app pack. Site recordings,
page prose, and notation images still do not enter the APK: every Pack 1 app clip remains a
synthesised in-repo asset as recorded above.

`site/public/data/maqams.json` is rebuilt by `tools/build_site_game_data.py`. Crawl fields (names,
pack assignment, scale notes, notation image paths, track metadata and audio paths) come from the
database; authored fields (`name_ar`, `color`, `jins_ar`, `signature_ar`, `status`, `app_audio`,
`drone`) and the `onboarding`/`lessons` blocks are carried over from the existing JSON and must be
edited there. Asset paths are relative to `site/public/data/`.

`tools/sync_app_pack.py` writes `app/src/main/assets/content/maqams.json` from the approved Pack 1
entries; it fails if a referenced bundled clip is missing. It also publishes the app-shaped
`site/public/data/pack.json` and mirrors the same referenced clips to
`site/public/data/app-audio/`. Those published files are byte-for-byte copies of the in-repo CC0
synthesised clips, so the licensing above covers them; the site origin serves only the same three
Pack 1 phrases, never MaqamWorld recordings.

Before publishing, file the written approval with the scope it covers (web hosting, recordings,
attribution wording) and keep the crawl out of release artifacts.
